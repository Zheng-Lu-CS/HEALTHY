# 项目工作流（快速上手版）

下面是**一步步**的流程，尽量用同学能理解的语言，不强行用医学术语。

## 0. 数据与输入
- 原始数据：`data/数据导出-202602.xlsx`（6025 × 361）
- 编码字典：`data/编码.docx`（把 0/1/2 等编码映射成中文类别）——比如婚姻状况中在婚同住=1 在婚分居=2 离婚=3 丧偶=4 其他=5
- 相关文献综述：见 `handover_cn/03_论文借鉴_对标与可吸收.md`

## 1. 数据清洗与缺失处理（D1）
- 统一缺失标记：`ND/UK/NA/空串` → 属于missing类（**注意 0 是合法值，不当缺失**）——这里的ND/UK/NA在数据中全是空字符串，并没有出现ND/UK/NA，应该是数据提供方的问题，毕竟这份数据中本身连地区有的都没有，可能不是特别严谨
- 类别特征：缺失保留为 “Missing” 类别
- 数值特征：用中位数插补
- 缺失率 ≥95% 的列直接丢弃
- 生成缺失统计与分布图、异常值报告

输出：
- `reports/D1_data_audit_report.md`——对数据的分析
- `figures/D1_*.png`——figures中所有的D1打头的图片，注意横坐标的含义需要在编码.docx中对应
- `figures/FIGURE_NOTES.md`（图像文字版）——这个md文档是当时由于中文编码出来可视化到图片上出现了比较严重的乱码，因此就让AI将所有图片中的数据中转化成文字版。后续有将编码问题改成了过来，大部分图片都没有问题，但是还有几张存在乱码现象，可以借助这个markdown文件进行分析

## 2. IC 代理评分（D2）
因为没有完整 ICOPE Step2 量表体系，我们用“**可解释的 proxy 规则**”构造 5 个 IC 域：
- 感官（听/视）
- 活力（营养、体重、BMI、小腿围）
- 运动（步态、步行困难、SPPB、握力）
- 认知（认知总分阈值）
- 心理（心理总分阈值/焦虑抑郁诊断）

每域 0/1 → `IC_total` = 5 域求和 → `IC_level` 分层。

输出：
- `reports/IC_RULES_SPEC.md`（规则说明）——这个规则中和我们会议上面说的一样，都是非黑即白式的打分，比如说步态异常=1 OR 250m步行困难=1 OR 肌少症-步行困难>=1 OR 运动-总分<=9 OR 握力低 (男<28, 女<18).1表示受损，0表示未受损
- `outputs/D2_with_IC.csv`（全样本 + IC 字段）——这就是我们会议上面查看的含有IC打分的文档

## 3. 表征学习（Embedding）
- 数值：z-score 标准化
- 类别：one-hot，低频 (<0.5%) 合并为 “Other”
- 模型：MLP AutoEncoder（32 维度）——就是一个多层感知机，逐步降维成32维度的向量（ input -> 256 -> 128 -> 32 -> 128 -> 256 -> input），input维度是989维（对原始的361向量部分特征类别进行了独热编码），个人感觉32维度的潜变量会损失很多信息，并且在这样反向decoder出来对标每一个输入，也就是989维度，感觉不太合适，这个后续可以考虑更换表征学习方式或者调整中间层的维度。标签是掩码重建。

输出：
- `outputs/D3_embeddings.parquet`（每个样本 32D embedding）——这个文档中存放这每个样本的embedding，没错的话是6025*989
- `reports/EMBEDDING_MODEL_CARD.md`——这个文档中详细记录了表征学习的模型和参数

## 4. 聚类分型（D3）
- KMeans / GMM 对比，K 从 2–10，指标：silhouette + CH + 稳定性 ARI
- 为了论文可解释性，最终在 3–6 里选最优 K（当前是 K=6）
- 输出 UMAP 可视化 + IC 雷达图

输出：
- `outputs/D3_cluster_assignments.csv`——每个样本的IC得分和所属聚类类别
- `outputs/D3_cluster_profiles.xlsx`——这个表中有两个子表，一个是每个簇的数量，另一个是每个簇对应的989维度的embedding均值
- `figures/D3_umap_clusters.png`——聚类可视化
- `figures/D3_radar_by_cluster.png`——每个类别的五个维度IC得分均值的雷达图
- `reports/CLUSTER_MODEL_CARD.md`——聚类的分析和说明

## 5. 重要性解释（D4）
- 目标1：预测 `IC_level`（多分类）
- 目标2：预测 `cluster_id`（多分类）
- 模型：XGBoost + SHAP
- 输出全局重要性与方向性解释

输出：
- `outputs/D4_feature_importance_IC.csv`——对于IC得分每个特征的SHAP均值得分，越大贡献越显著
- `outputs/D4_feature_importance_cluster.csv`——对于聚类分型每个特征的SHAP均值得分，越大贡献越显著，也就是表达了每个变量影响分型的重要性
- `outputs/D4_feature_importance_IC_noleak.csv`（去泄露敏感性）——SHAP Top 特征里出现了大量“Fried握力、4米行走、运动总分、跌倒总分”等功能测试项。这些字段也参与了 IC 代理构造或与 IC 的定义高度重叠，导致了信息泄露。这是去泄露之后的重要性得分。可以使用去泄露和泄露（也就是D4_feature_importance_IC.csv）进行敏感性分析
- `figures/D4_shap_summary_*.png`——这张图片出现了乱码，可以直接看figures/WIGURE_NOTES.md文件中最下方关于这张图的文字描述，就是总结一下这是个因素对于IC的得分贡献程度
- `figures/D4_dependence_IC_01..10.png`——这是张图片展示了影响IC得分的十个特征的SHAP值
- `reports/SHAP_INTERPRETATION_GUIDE.md`——对SHAP的介绍和计算规则
- `reports/SHAP_DEPENDENCE_SUMMARY.md`——影响IC得分的十个特征的SHAP值的一个文字描述

## 6. 泄露检查（非常关键）
- 识别“**和 IC 定义重复**”的字段（如握力、SPPB、认知总分）
- 做 A/B 两次重要性，比较 Top20 重叠
- 结果：重叠很低 → 说明如果不去除，会“自证式”夸大重要性

输出：
- `reports/LEAKAGE_CHECK.md`——这个泄露的问题我目前不太理解，感觉上可能和多重共线性有点像（？），不过看起来这是一个严谨性上的大问题
